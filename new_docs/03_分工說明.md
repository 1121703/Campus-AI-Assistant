## 成員 A｜登入後主頁面（儀表板）

### 負責檔案
- `Final/dashboard/dashboard.html`
- `Final/dashboard/assets/css/app.css`
- `Final/dashboard/assets/js/app-core.js`
- `Final/dashboard/assets/js/dashboard.js`
- `Final/dashboard/assets/js/nav.js`（共用導航列，其他頁面也引用）
- `Final/api/dashboard.py`

### 技術說明

**1. 儀表板 UI（dashboard.html + app-core.js）**
- 登入後第一個畫面，包含：本週任務總覽、今日建議、每週登入分鐘數統計圖
- `app-core.js` 負責初始化應用程式狀態，掛載各元件
- `nav.js` 是整個系統的共用導航列（sidebar），所有登入後頁面都引用此檔，渲染左側功能選單

**2. 每日建議引擎（api/dashboard.py）**
- 規則引擎自動根據近期任務截止日、測驗結果、登入行為生成建議
- 建議存入 `daily_suggestions.json`，每天產生一次
- API：`GET /api/daily-suggestions?user_id=xxx`
- 使用者可對建議標記「完成（done）」或「略過（skip）」→ 更新 `daily_suggestions.json` 的 `status`

**3. 週指標統計（dashboard_metrics_weekly.json）**
- 每次登出時計算本次登入分鐘數，累積到 `daily_login_minutes`
- 任務完成時更新 `tasks_done`
- API：`GET /api/dashboard/metrics?user_id=xxx&week_start=YYYY-MM-DD`

**4. 儀表板狀態持久化（dashboard_state.json）**
- 使用者選中的週、是否顯示已完成任務、哪些卡片被摺疊
- 每次 UI 狀態改變時 POST 到 `/api/data/dashboard_state.json`
- 頁面重載時自動還原上次的檢視狀態

**5. 資料存取控制（api/dashboard.py）**
- 前端可直接透過 `/api/data/{filename}` 讀寫白名單內的 JSON 檔案
- 白名單限制哪些檔案可被前端直接存取，防止越權

## 成員 B｜行事曆

### 負責檔案
- `Final/calnader/calendar.html`
- `Final/calnader/css/calendar.css`
- `Final/calnader/js/api.js`
- `Final/calnader/js/auth.js`
- `Final/calnader/js/main.js`
- `Final/calnader/js/utils.js`
- `Final/api/calendar.py`

### 技術說明

**1. 行事曆 UI（calendar.html + main.js）**
- 月曆視圖 + 任務清單，支援日期點選查看當天事件/任務
- 任務可直接在頁面上完成、刪除、新增
- `auth.js` 負責頁面載入時確認登入狀態（`localStorage.getItem('auth_user_id')`）
- `utils.js` 提供日期格式化、時間顯示等工具函式

**2. 任務 CRUD API（api/calendar.py）**

```
GET    /api/calendar/tasks?user_id=xxx           ← 取得所有任務
POST   /api/calendar/tasks                       ← 新增任務
GET    /api/calendar/tasks/{task_id}             ← 查單一任務
PUT    /api/calendar/tasks/{task_id}             ← 更新任務
DELETE /api/calendar/tasks/{task_id}             ← 軟刪除（status→archived）
POST   /api/calendar/tasks/{task_id}/complete    ← 完成任務（status→completed）
```

**3. 事件 CRUD API**

```
GET    /api/calendar/events?user_id=xxx          ← 取得所有事件
POST   /api/calendar/events                      ← 新增事件
GET    /api/calendar/events/{event_id}           ← 查單一事件
PUT    /api/calendar/events/{event_id}           ← 更新事件
DELETE /api/calendar/events/{event_id}           ← 刪除事件
```

**4. 稽核紀錄（calendar_audit_log.json）**
- 所有任務/事件的 CRUD 操作都自動寫入 audit log
- 記錄格式：`action`（操作類型）、`target_id`（被操作項目）、`detail`（變更前後差異）

**5. 全天事件處理**
- `all_day: true` 的事件（如假日、期末週）在 AI 排程衝突偵測時會被跳過
- 確保全天性標記事件不阻擋一般排程

## 成員 C｜AI 助手頁面

### 負責檔案
- `Final/ai-assistant/ai-assistant.html`
- `Final/ai-assistant/js/data-manager.js`
- `Final/ai-assistant/js/scheduler.js`（聊聊 Tab）
- `Final/ai-assistant/js/counseling.js`（心理分析 Tab）
- `Final/api/ai.py`

### 技術說明

**1. 前端頁面（ai-assistant.html）**
- 兩個 Tab：「聊聊」（一般對話 + 排程）、「心理分析」（輔導員對話 + 測驗報告）
- 引用 `dashboard/assets/js/nav.js` 共用導航列
- 登入驗證：`localStorage.getItem('auth_user_id')`，未登入跳回 `/login`

**2. API 封裝層（data-manager.js）**
- 統一管理所有後端 API 呼叫，其他 JS 模組只需呼叫 DataManager 的方法
- 主要方法：
  - `sendChatMessage(message, history)` → `POST /api/ai/chat`
  - `sendCounselorMessage(message, history)` → `POST /api/ai/counselor_chat`
  - `acceptSchedule(suggestion)` → `POST /api/ai/accept_schedule`
  - `getCalendarEvents()` → `GET /api/ai/calendar_events`
  - `getPsychReport(userId)` → `GET /api/ai/psych_report`
  - `formatDateTime(value)` / `formatTime(value)` / `escapeHtml(text)`

**3. 聊聊模組（scheduler.js）**
- 維護對話 history（最多 10 條，5 輪）
- 送出前做 prevHistory snapshot，成功後才將本輪 user + AI 回覆存入 history
- 若後端回傳 `schedule_suggestion`，渲染「排程建議卡片」
- 點擊「接受建議」→ `ChatModule.acceptSuggestion()` → 呼叫後端 accept_schedule → 刷新行事曆

**4. 心理分析模組（counseling.js）**
- 同樣維護對話 history，上下文記憶機制與聊聊相同
- 頁面切換到心理分析 Tab 時，自動載入最近 5 筆 psych_results 的 AI 摘要報告
- 輔導員對話會附帶近期測驗資料作為 AI 背景資訊（system prompt 注入）

**5. 後端 AI 邏輯（api/ai.py）**

*排程解析流程：*
```
使用者輸入
  ↓ _is_schedule_related()       ← Ollama 判斷 + 規則引擎兜底
  ↓ _extract_date()              ← regex：6/20 → 2026-06-20
  ↓ _extract_time()              ← regex：8.30 / 8:30 / 8點半 → (8, 30)
  ↓ _extract_duration()          ← regex：2小時 / 30分 → 120 / 30
  ↓ _ai_extract_title()          ← Ollama 萃取事件名稱（僅此步驟用 AI）
  ↓ _next_available_slot()       ← 查 calendar_events，跳過 all_day，找無衝突時段
  ↓ _build_schedule_reply()      ← Ollama 生成自然語言確認回覆
  ↓ 回傳建議卡片（前端「接受建議」前不寫入行事曆）
```

*Ollama 整合：*
- 模型：`qwen3:1.7b`（本地端 Ollama）
- 回覆後自動剝除 `<think>...</think>` 思考標籤
- 所有 Ollama 呼叫都有 `fallback` 兜底，避免模型離線導致服務中斷

*上下文記憶：*
- `_ollama_chat_with_history(system_prompt, history, user_message)` 最多保留最近 10 條
- 排程判斷（`_is_schedule_related`）不使用 history，每次獨立判斷
- 一般聊天與心理輔導都帶入 history

**6. AI 資料日誌**
- 所有對話寫入 `ai_prompt_log.json`（含 user 輸入與 AI 回覆）
- 排程建議寫入 `ai_schedule_suggestions.json`（待接受的建議）
- 接受建議後寫入 `ai_schedule_merge_log.json`（已接受紀錄）
- JSON 讀寫採用 `.bak` 備份機制，解析失敗時自動從備份復原

## 成員 D｜遊戲化模組 + 心理測驗

### 負責檔案
- `Final/game/game.html`
- `Final/game/css/game.css`
- `Final/game/image/`（所有遊戲圖檔）
- `Final/game/js/game.js`
- `Final/api/game.py`
- `Final/psych/psych_index.html`
- `Final/psych/js/psych_main.js`
- `Final/api/psych.py`

### 技術說明

**1. 遊戲模組（game.html + game.js）**
- 學習遊戲化，玩家需在時間內回答問題或完成任務
- 三種難度：`easy`（簡單）、`normal`（普通）、`hard`（困難）
- 遊戲結束後自動上傳成績：`POST /api/game/sessions`
- 難度選擇記錄：`POST /api/game/settings`（每次更改都 append 一筆，取最新一筆為設定）

*後端 API（api/game.py）：*
```
POST /api/game/sessions   ← { user_id, difficulty, score, duration_sec }
POST /api/game/settings   ← { user_id, difficulty_default }
```

**2. 心理測驗（psych_index.html + psych_main.js）**
- 使用者完成 5 題測驗，每題選項有 `stress_weight` 和 `energy_weight`
- `psych_main.js` 流程：
  1. 呼叫 `GET /api/psych/questions` 取得 5 道隨機題目
  2. 使用者逐題作答，本地累計分數
  3. 完成後 `POST /api/psych/results` 送出答案
  4. 後端計分 → 呼叫 Ollama 生成個人化摘要 → 回傳結果
  5. 前端顯示壓力等級、AI 摘要、建議

*後端 API（api/psych.py）：*
```
GET  /api/psych/questions?user_id=xxx&count=5    ← 隨機抽取 5 道題
POST /api/psych/results                          ← { user_id, session_id, answers }
GET  /api/psych/results?user_id=xxx&limit=5      ← 取最近 N 筆結果
```

**3. 計分機制**
- 題庫每題有多選項，每個選項有 `stress_weight`（壓力貢獻）和 `energy_weight`（能量貢獻）
- `score_total`：所有選項的 `stress_weight` 總和
- `scale_scores.stress`：對應 0–100 標準化壓力指數
- `scale_scores.energy`：對應 0–100 標準化能量指數
- 依 `psych_scoring_rules.json` 的 `thresholds` 分級：
  - 0–50 → `低壓力`
  - 51–75 → `中度壓力`
  - 76–100 → `高壓力`

**4. AI 題目生成**
- 題庫不夠時可呼叫 Ollama（qwen3:1.7b）生成新題目
- 生成紀錄存入 `psych_ai_question_log.json`
- 新題目自動加入 `psych_question_bank.json`

### 技術說明

**1. 落地頁（final.html）**
- 系統介紹、功能說明
- 使用 jQuery + breakpoints.min.js 實現響應式設計
- `nav-prelogin.js`：登入前導覽列邏輯（跳轉至 login / register）
- `jquery.scrollex.min.js`：卷軸動畫效果

**2. 登入頁面（login.html + login.js）**
- 表單驗證：Email 格式、密碼非空
- `POST /api/auth/login`：`{ email, password }`
- 成功後：
  ```javascript
  localStorage.setItem('auth_user_id', data.user_id)
  localStorage.setItem('auth_user_name', data.name)
  window.location.href = '/dashboard'
  ```
- 失敗時顯示錯誤訊息（Email 不存在、密碼錯誤）

**3. 註冊頁面（register.html + register.js）**
- 表單驗證：Email 格式、名稱非空、密碼長度、兩次密碼確認
- `POST /api/auth/register`：`{ name, email, password }`
- 成功後跳轉至 `/login`

**4. 後端認證（api/auth.py）**

*註冊流程：*
```python
POST /api/auth/register
  → 驗證 email 唯一性（比對 users.json）
  → 密碼雜湊：sha256(password) 存為 "sha256:{hex}"
  → 指派 user_id：取現有最大流水號 + 1（格式 u_XXXX）
  → append 到 users.json
  → 回傳 { ok: true, user_id, name }
```

*登入流程：*
```python
POST /api/auth/login
  → 根據 email 找到使用者（比對 users.json）
  → SHA-256(password) == stored hash → 驗證成功
  → 建立 session：session_id = s_XXXX，login_at = now()，active = true
  → append 到 login_sessions.json
  → 回傳 { ok: true, user_id, name }
```

*登出流程：*
```python
POST /api/auth/logout
  → 找到 user_id 最新的 active session
  → 更新：logout_at, duration_sec = (now - login_at).seconds, active = false
  → 清除前端 localStorage（由前端 JS 執行）
```
