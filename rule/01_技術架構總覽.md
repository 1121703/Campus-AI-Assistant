# Campus AI — 技術架構總覽

## 系統簡介

Campus AI 是一個以 Python 純標準庫 HTTP Server + 前端靜態 HTML/JS 為核心的大學生校園助手平台，整合了登入認證、行事曆任務管理、AI 聊天排程、心理壓力測驗、遊戲化學習五大模組。

---

## 技術選型

| 層級 | 技術 |
|---|---|
| 後端伺服器 | Python 3 `ThreadingHTTPServer`（`http.server`），無框架 |
| 前端 | 原生 HTML5 + CSS3 + Vanilla JS（部分頁面使用 jQuery） |
| 資料儲存 | JSON 檔案（`Final/data/*.json`），無資料庫 |
| AI 推理 | Ollama 本地端 `qwen3:1.7b`（主）、Google Gemini API（部分功能備用） |
| 密碼安全 | SHA-256 雜湊，格式 `sha256:<hex>` |
| 時區 | 台灣時間 UTC+8，ISO 8601 格式 `YYYY-MM-DDTHH:MM:SS+08:00` |

## 後端路由架構（main.py）

`main.py` 用一個 `ROUTE_MAP` 字典，把 URL 前綴對應到各 `api/*.py` 的 `handle()` 函式：

```python
ROUTE_MAP = {
    "/api/auth/":      auth.handle,
    "/api/calendar/":  calendar.handle,
    "/api/game/":      game.handle,
    "/api/psych/":     psych.handle,
    "/api/ai/":        ai.handle,
    # /api/health, /api/daily-suggestions, /api/dashboard/, /api/data/ → dashboard.handle
}
```

每個 API 模組都實作同一介面：

```python
def handle(method: str, path: str, body: dict | None, params: dict) -> tuple[int, dict]:
    # method: "GET" | "POST" | "PUT" | "DELETE"
    # path:   完整路徑，如 "/api/calendar/tasks"
    # body:   POST/PUT 的 JSON body（已解析為 dict）
    # params: URL query string（已解析為 dict of lists）
    # 回傳: (HTTP status code, response dict)
```

主要靜態頁面路由：
- `/` → `before_login/final.html`（落地頁）
- `/login` → `before_login/login.html`
- `/register` → `before_login/register.html`
- `/dashboard` → `dashboard/dashboard.html`
- `/calendar` → `calnader/calendar.html`
- `/game` → `game/game.html`
- `/psych` → `psych/psych_index.html`
- `/ai-assistant` → `ai-assistant/ai-assistant.html`

## 認證流程

```
[前端] login.html
  ↓  POST /api/auth/login  { email, password }
[後端] auth.py
  ↓  SHA-256(password) 比對 users.json
  ↓  建立 session → login_sessions.json
  ↓  回傳 { ok: true, user_id, name }
[前端] localStorage.setItem('auth_user_id', user_id)
       localStorage.setItem('auth_user_name', name)
  ↓  
重導向到 /dashboard
```

登出時：
```
POST /api/auth/logout { user_id }
→ 更新 login_sessions.json 的 logout_at / duration_sec / active=false
→ 清除 localStorage
```

各頁面在 `DOMContentLoaded` 時檢查 `localStorage.getItem('auth_user_id')`，若為空則跳回 `/login`。

## 資料讀寫模式（api/utils.py）

所有 JSON 檔都遵循同一結構：

```json
{
  "schema_version": 1,
  "items": [ ... ]
}
```

`utils.py` / `ai.py` 提供的 I/O 函式：

| 函式 | 說明 |
|---|---|
| `read_json(name)` | 讀取 `data/{name}`，失敗時回傳空結構 |
| `write_json(name, data)` | 先寫 `.tmp` 再 `os.replace`，防止寫到一半損壞 |
| `append_item(name, item)` | 讀 → append → 寫，atomic-ish |
| `_write_json` (ai.py) | 額外備份 `.bak`，解析失敗時自動復原 |

## AI 模組架構（api/ai.py）

```
使用者輸入
  │
  ├─ _is_schedule_related()  ← 判斷是否排程相關（Ollama + 規則引擎）
  │
  ├─ [排程相關]
  │   ├─ _extract_date()      ← regex 解析日期（6/20 → 2026-06-20）
  │   ├─ _extract_time()      ← regex 解析時間（8.30 / 8:30 / 8點30分）
  │   ├─ _extract_duration()  ← regex 解析時長（2小時、30分）
  │   ├─ _ai_extract_title()  ← Ollama 只萃取事件名稱
  │   ├─ _next_available_slot() ← 查 calendar_events.json 找可用時段
  │   │    （all_day 事件跳過，不算衝突）
  │   └─ _build_schedule_reply() ← Ollama 生成自然語言回覆
  │
  └─ [一般聊天]
      └─ _build_normal_reply() ← Ollama + 對話 history
```

對話 history（上下文記憶）：
- 前端維護 `history[]`，最多 10 條（5 輪）
- 每次 API 呼叫傳入前一輪的 history（不含本輪 user 訊息）
- 成功後才把本輪 user + AI 回覆存入 history
- 後端 `_ollama_chat_with_history()` 最多取最後 10 條

## 時間格式規範

系統統一使用台灣時間（UTC+8）：

```python
TZ = timezone(timedelta(hours=8))

# 格式範例
"2026-06-20T08:30:00+08:00"   # 標準格式（首選）
"2026-06-20T00:58:00.000Z"    # UTC（部分舊資料，_parse_dt 會自動轉換）
```

`_parse_dt()` 支援兩種格式並統一轉為 `+08:00`。
